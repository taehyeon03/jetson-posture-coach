# 중간 발표 준비 역할 분담

작성일: 2026-10-06. 팀 소개 슬라이드의 역할을 기준으로 정리한 작업 분담안이다.
개별 일정과 웹 기능 구현 담당은 팀 내 합의가 필요하다.

중간 발표는 각 피드백을 **기존 상태(As-is) → 수행한 개선·검증 → 반영된 결과와 증거 → 남은 한계** 순서로 설명한다.
방향 결정, 예비 실험, 구현 완료를 구분하며 아직 수행하지 않은 작업을 완료 결과로 표시하지 않는다.

## 작업 순서와 협업

1. **탁윤성 → 김태현·변대필:** 측정할 관절·각도와 모델 후보를 제안한다. 의학 논문 기준의 측정 자세·관절 정의가 우리 카메라 측정과 맞는지도 정리한다. 김태현이 구현 범위를 조율하고 변대필이 평가 기준을 함께 정한다.
2. **김민석 → 김태현·변대필:** 카메라 설치 조건을 고정하고 시험 가능한 환경을 준비한다. 원본 프레임 수집 조건은 모델 평가 담당과 맞춘다.
3. **김태현 → 변대필·김민석:** 실행 가능한 모델·시스템과 재현 명령을 전달한다. 변대필은 인식 품질, 김민석은 장치 성능·안정성을 검증한다.
4. **김찬영 ↔ 김태현:** 기록·화면 구조는 먼저 설계하되, 측정 항목 확정 후 데이터 필드와 계산식을 맞춘다. 로그인·저장·화면의 실제 구현 담당은 김태현이 조율한다.
5. **전원 → 김태현:** 아래 공통 형식으로 결과와 근거를 전달하고 통합 발표 자료에 반영한다.

## 공통 제출 형식

- **피드백 항목:** 어떤 요구를 다뤘는가.
- **기존 상태(As-is):** 기존 기능과 문제를 설명한다.
- **수행한 작업:** 조사·설계·실험·구현 중 무엇을 했는지 명시한다.
- **반영된 결과:** 비교 이미지, 측정표, 실행 로그 또는 시연으로 뒷받침한다.
- **남은 한계·다음 작업:** 미완료 항목과 필요한 결정을 기록한다.

수치에는 장치·모델·실험 조건·반복 횟수를 함께 적는다. 화면 시안의 예시 데이터는
실측 데이터와 구분하고, 코칭 효과가 검증되지 않았다면 개선 효과로 단정하지 않는다.

## 현재 판단에 반영할 사항

- SpinePose는 개발 PC 예비 시험까지 진행됐으며, Jetson 변환·실제 카메라 검증은 남아 있다. 채택 완료로 발표하지 않는다.
- 예비 시험에서 등 굽음 표현과 C7 위치의 한계가 확인됐다. 출력 관절 수 증가만으로 정확도가 개선됐다고 판단하지 않는다.
- 모델 개수를 하나로 제한하지 않는다. 모터·웹·음성 등을 포함한 전체 시스템의 Nano 4GB 메모리 예산 안에서 검증한다.
- 의학 기준과 개인 기준의 역할, 측정 각도, 코칭 지표는 아직 합의할 항목이다.
- 현재 팀 역할표에는 웹 개발 전담자가 없다. 김찬영의 시각화 설계와 로그인·저장 기능 구현 책임을 구분해 담당을 확정한다.
- GPIO 작업 전 커스텀 캐리어보드의 실제 핀맵을 확인한다.
