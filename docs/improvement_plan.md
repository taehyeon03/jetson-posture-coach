## 1. 관절 위치 튐 차단과 상태 안정화

### 현재 상태

이미 들어가 있는 안정화 장치:

- `KeypointSmoother` — 관절별 One-Euro 필터(`src/posture.py`)
- `SteadyMetrics` — 지표가 사라져도 0.6초 동안 직전 값 유지
- `SustainedAlert` — 같은 나쁜 상태가 3초 지속되면 알림 1회

그런데도 기대기 조건에서 상태가 계속 바뀐다.

| run | 프레임 | 상태 전환/분 | `torso_forward` 0.06 이상 급변 | 상태 분포 |
| --- | ---: | ---: | ---: | --- |
| `20260927-233623-chair-leaning-official` | 234 | 85.5 | 33% | HEAD 140 / TORSO 79 / GOOD 15 |
| `20260928-001529-cac5g-tts-backrest-leaning` | 213 | 59.3 | 26% | TORSO 160 / GOOD 49 / HEAD 4 |
| `20260927-233826-chair-no-backrest-official` | 249 | 1.8 | 0% | TORSO 248 / BOTH 1 |

### 원인 분석

- 임계값 근처의 작은 떨림이 아니다. 기대기 run의 `(head_forward, torso_forward)`는
  **두 값 묶음 사이를 프레임마다 오간다.** 예: `(0.00, -0.12)` ↔ `(0.11, -0.23)`.
- 두 값이 함께 0.11–0.12씩 바뀐다. 따라서 엉덩이(또는 어깨) 점이 등받이·좌판 경계의 서로
  다른 두 위치를 번갈아 잡는 것으로 보인다. 몸통 길이가 바뀌므로 `head_forward`도 따라 움직인다.
- One-Euro 필터는 빠른 움직임일수록 덜 걸러 내도록 설계됐다. 그래서 한 프레임짜리 큰 튐은
  그대로 통과한다.
- `SustainedAlert`는 나쁜 상태의 **종류**가 바뀌어도 타이머를 다시 시작한다.
  `HEAD_FORWARD` ↔ `TORSO_FORWARD`가 번갈아 나오면 계속 나쁜 자세여도 3초 알림이 울리지 않는다.
- 임계값 히스테리시스만 넣으면 튀는 폭(0.12)이 임계값(0.12–0.14)과 같아 효과가 작다.
  **튐을 먼저 막고, 그다음 상태를 안정화한다.**

### 변경 내용

1. **관절 튐 차단(`src/posture.py`)**
   - 엉덩이·어깨 점이 직전 프레임에서 몸통 길이의 `0.15`배 이상 한 번에 이동하면 그 프레임의
     해당 점을 버린다. 비율은 기존 `PersonLock`과 같은 방식이다.
   - 같은 방향으로 `3`프레임 연속 이동하면 실제 이동으로 보고 받아들인다.
   - 버린 프레임은 기존 `SteadyMetrics` 유예 시간으로 넘긴다.
   - CSV에 `hip_rejected` 열을 추가해 차단 비율을 기록한다.
2. **상태 히스테리시스(`classify`)**
   - 나쁜 상태로 **들어갈** 때는 지금 임계값(머리 0.14, 몸통 0.12)을 쓴다.
   - **나올** 때는 임계값에서 `0.03`을 뺀 값보다 낮아져야 한다.
   - 직전 상태를 알아야 하므로 `classify`를 상태를 가진 클래스로 감싼다.
     기존 함수 시그니처는 테스트를 위해 유지한다.
3. **표시 상태 유지 시간**
   - 화면과 로그의 상태는 새 상태가 `1.0`초 이상 이어질 때만 바꾼다.
     3.8 FPS 기준 약 4프레임이다.
4. **알림 타이머 정리(`SustainedAlert`)**
   - `HEAD_FORWARD`, `TORSO_FORWARD`, `HEAD_AND_TORSO_FORWARD`를 하나의 "나쁜 자세"로 묶어 타이머를 잰다.
   - 어떤 안내 문장을 쓸지는 알림 시점의 상태로 고른다.

위 숫자(0.15, 3프레임, 0.03, 1.0초)는 시작값이다. 기존 `frames.csv`를 재생해 고른 뒤
실측으로 확정한다.

### 완료 기준

- 기존 기대기 run 두 개를 재생했을 때 `torso_forward` 0.06 이상 급변 ≤ 5%,
  상태 전환 ≤ 6회/분.
- 새 실측(아래 프로토콜)에서 모든 조건의 상태 전환 ≤ 6회/분.
- 실제로 자세를 바꿨을 때 상태 변경까지 걸리는 시간 ≤ 2초.
  측정 방법: 바른 자세 → 숙이기 시점을 화면 녹화 시계로 기록한다.
- 같은 나쁜 자세를 5초 유지하면 알림이 정확히 1회 울린다.

## 2. 얼굴 검출 병목 제거

### 현재 상태

`web_mvp/server.py`는 매 프레임 Haar profile cascade를 원본과 좌우 반전본에 두 번 돌린다.
이 결과로 사람 영역(ROI)을 잘라 자세 모델에 넣는다.

| run | 얼굴 검출 중앙값 | 자세 추론 중앙값 | 프레임 전체 중앙값 | 얼굴 검출률 |
| --- | ---: | ---: | ---: | ---: |
| chair-leaning-official | 182 ms | 69 ms | 257 ms | 1% |
| chair-no-backrest-official | 184 ms | 68 ms | 259 ms | 2% |
| cac5g-tts-hands-on-thighs | 200 ms | 69 ms | 276 ms | 5% |
| cac5g-tts-backrest-leaning | 202 ms | 69 ms | 278 ms | 20% |
| cac5g-tts-backrest-clear | 204 ms | 68 ms | 280 ms | 32% |

- 프레임 시간의 약 70%를 얼굴 검출에 쓰지만 **대부분 얼굴을 찾지 못한다.** 얼굴을 못 찾으면
  ROI 없이 전체 화면으로 추론한다.
- 지금은 비용만 내고 "다른 사람 관절이 섞이는 것 방지"라는 원래 목적은 거의 수행하지 못한다.
- 검출률이 낮은 이유로 추정되는 것:
  - 0.4배로 줄인 뒤 최소 크기 24 px를 요구하므로, 원본에서 얼굴이 약 60 px 이상이어야 한다.
  - 측면 얼굴 일부가 가려지거나 기울어지면 profile cascade가 놓친다.

### 변경 내용

1. **ROI를 직전 자세 결과에서 만든다.**
   - 직전 프레임이 `PersonLock`을 통과했다면 코·귀·어깨·엉덩이 점을 감싸는 상자에 여유를 더해 ROI로 쓴다.
   - 이 경우 얼굴 검출은 건너뛴다.
2. **얼굴 검출은 필요할 때만 돌린다.**
   - 시작할 때, 사람을 잃었을 때(`PersonLock` 실패 `N`회), 그리고 주기적 재확인으로 `2`초에 한 번만 돌린다.
3. **얼굴 검출 자체를 가볍게 한다.**
   - 직전 얼굴 위치를 알면 그 주변 영역에서만 찾는다.
   - 사람이 바라보는 방향이 정해졌으면 반전 검출을 생략한다. 설치 위치가 고정이라 방향이 거의 바뀌지 않는다.
4. 2인 이상이 화면에 있을 때 관절이 섞이지 않는지는 기존과 같은 방식으로 확인한다.

### 완료 기준

- 1인 착석 60초에서 프레임 처리 중앙값 ≤ 150 ms, 평균 FPS ≥ 5.
- `face_ms` 평균 ≤ 30 ms. 대부분의 프레임에서 0이어야 한다.
- 2인 동시 노출 60초에서 다른 사람에게 잠금이 넘어간 프레임 0건.
  화면 녹화로 확인하고 `lock_ok` 비율을 함께 기록한다.
- 위 개선으로 생긴 여유 시간은 SpinePose 추가 시 추론 시간 예산으로 쓴다.

## 3. 엉덩이 누락 대응

### 현재 상태

- `extract_metrics()`는 코·귀·어깨·엉덩이가 모두 confidence 0.25 이상이어야 지표를 만든다.
- 엉덩이 평균 confidence가 0.25–0.38에 몰려 있어 작은 자세 변화로도 판정 불가가 된다.
  손을 들고 기대지 않는 같은 조건을 반복했을 때 86% / 29%가 나왔다.
- `SteadyMetrics` 유예 0.6초는 3.8 FPS에서 2프레임 정도라 짧다.

### 변경 내용

1. **유예 시간을 늘린다.** 엉덩이만 빠진 경우 직전 엉덩이 위치와 몸통 길이를 최대 `2`초 유지한다.
   - 사람이 자리를 떠났는지는 코·귀·어깨도 함께 사라졌는지로 판단해, 떠난 경우는 바로 `NO_POSE`로 간다.
2. **고개 전진 단독 판정 모드를 둔다.**
   - 엉덩이가 2초 넘게 없으면 귀–어깨 수평 거리를 보정 시 저장한 몸통 길이로 나눠
     `head_forward`만 계산한다.
   - 상태는 `HEAD_ONLY` 표시와 함께 `HEAD_FORWARD` / `GOOD`만 낸다.
   - 몸통 숙임 판정은 보류한다고 화면에 알린다.
   - 이를 위해 보정 파일(`Baseline`)에 몸통 길이 중앙값을 추가한다. 버전을 2로 올리고 1도 읽을 수 있게 한다.
3. **설치 위치를 고정한다.**
   - 바닥·좌판에 의자 위치를 표시하고, 카메라 높이·거리·각도를 [하드웨어 기록](hardware_notes.md)에 남긴다.
   - 김민석님의 설치 조건표와 연동한다.

### 완료 기준

- 아래 프로토콜 5개 조건 × 3회에서 판정 가능률(`GOOD`·나쁜 자세 중 하나로 판정된 프레임 비율) ≥ 90%.
- `HEAD_ONLY` 비율을 함께 보고하고, 30% 이상이면 카메라 배치를 다시 검토한다.

## 4. 보정 품질 검사

### 현재 상태

- 비기대 run은 249프레임 중 248프레임이 `TORSO_FORWARD`였다. 같은 날 다른 자세(기대기 등)로
  저장한 기준을 그대로 쓴 것으로 보인다.
- 지금 보정은 5초 동안 모은 값의 중앙값만 저장하고, 그 사이의 흔들림이나 유효 프레임 비율은 검사하지 않는다.

### 변경 내용

- 보정 중 `head_forward`·`torso_forward`의 사분위 범위(IQR)를 계산한다.
  둘 중 하나가 `0.05`를 넘으면 "움직임이 커서 다시 보정" 메시지를 띄우고 저장하지 않는다.
- 보정 파일에 IQR, 유효 프레임 비율, 몸통 길이, 생성 시각을 저장하고 벤치마크 `config.json`에도 기록한다.
- 기댄 자세와 바로 앉은 자세에 기준을 따로 둘지는 라운드 3(의학 기준과 개인 기준의 역할) 결정 후 정한다.

### 완료 기준

- 일부러 움직이며 보정하면 거부된다.
- 바른 자세로 보정한 직후 같은 자세 60초에서 `GOOD` 비율 ≥ 90%.

## 검증 프로토콜

1–4의 효과를 같은 조건으로 비교하기 위한 측정 방법이다.

  - 의자 다리 위치와 카메라 삼각대 위치를 바닥에 테이프로 표시한다.
  - 카메라 높이·거리를 기록한다.
  - 전원 모드는 `MAXN`으로 고정한다.
- **조건 5개:** 09-28과 같다(손 허벅지/가슴 × 등받이 기대기/안 기대기 + 결합 조건).
- **반복:** 조건당 3회. 조건 순서는 회차마다 무작위로 섞는다.
- **측정:** 워밍업 5초 후 60초, `scripts/benchmark.py run`.
  - 개선 전 코드(현재 `main`)와 개선 후 코드를 같은 날 같은 배치에서 번갈아 측정한다.
- **기록할 값:**
  - 상태 전환/분
  - 판정 가능률
  - `torso_forward` 급변 비율
  - 프레임 처리 중앙값·p95
  - FPS, RSS peak
- **보고:** 조건별 평균과 최소·최대를 표로 남기고, 결과는 `docs/`에 날짜별 문서로 추가한다.
- **가능하면:** 2명 이상이 측정한다. 1명 결과는 탐색 결과로 표시한다.

for d in sorted(glob.glob("benchmarks/jetson-runs/*/")):
    rows = list(csv.DictReader(open(d + "frames.csv")))
    if not rows or not rows[0].get("face_ms"):

    states = [r["state"] for r in rows]
    dur = float(rows[-1]["t_s"]) - float(rows[0]["t_s"])
    torso = [float(r["torso_forward"]) for r in rows if r["torso_forward"]]
    jumps = [abs(a - b) > 0.06 for a, b in zip(torso, torso[1:])]
